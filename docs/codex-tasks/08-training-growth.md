# 训练成长功能

2026-10-16 用户授权实现七项功能。沿用当前原生小程序 UI 与本地历史数据，不提交或发布。

1. 单动作曲线：按动作身份合并历次最大重量与估算 1RM，30/90 天与全部范围；从动作详情、训练与个人纪录进入。
2. 提醒：用户确认“还没有，先完成配置入口”，本轮完成本地偏好入口，默认 20:00，显示尚未配置及未来训练日预览。订阅授权、发送云函数与定时触发待提供模板后接入，当前不发送消息。
3. 组类型：正式组、热身组、递减组；超级组将两个动作交替记录。旧组默认为正式组。热身组排除个人纪录与加量建议，递减组计入训练量与纪录但不用于加量判定。
4. 周报：周一及以后首次打开今天页，自动计算上一完整周的报告；有数据且未读时显示入口。含训练次数、训练量、新纪录、记录日平均摄入与体重变化，支持图片保存和小程序分享。
5. 完成训练卡：保存完成的训练后生成可导出的卡片，显示实际完成组的训练量与新纪录。
6. 常吃与复制：收藏食物后快速记录；从昨天选择一餐复制，生成新 ID、今日时间、保留份量营养值。
7. 星期课表：每计划独立切换循环/星期模式，星期模式允许未排课日休息；今天、周节奏和提醒采用同一排课规则。

验收关注：旧记录兼容、身份冲突、无效训练组、热身排除、跨年周报边界、无记录与仅单次体重、复制不改旧记录、提醒未配置状态、页面入口可达、图片导出失败可恢复。真实设备相册/转发验收与后续订阅消息部署单独记录。

## 已实现入口

| 功能 | 入口 | 关键行为 |
| --- | --- | --- |
| 动作曲线 | 动作详情、训练记录页、统计中的全部个人纪录 | 30/90 天和全部；最大重量及估算 1RM；历史点可打开当天记录 |
| 提醒设置 | 我的 → 训练提醒 | 保存本地开关、时间；跟随当前计划预览未来两周中的前 5 个训练日；明确尚未配置推送 |
| 组类型 | 训练记录页 → 点组号或“添加训练组” | 热身不计纪录和训练量；递减计纪录但不参与加量；超级组配对后 A/B 交替，一轮后休息 |
| 周报 | 我的 → 训练周报；今天页的未读周报入口 | 上一完整周，可查看更早一周；无饮食显示未记录，体重不足两次不显示变化 |
| 训练分享 | 结束训练；历史当天详情 → 生成训练分享卡片 | 原生 Canvas 导出 750×1120 PNG；可转发小程序或保存后手动发朋友圈 |
| 饮食快捷 | 饮食 → 复制昨天的一餐；餐食详情 → 加入常吃 | 按原份量添加，生成新 ID、今天的时间；保留昨天数据；收藏优先于自动统计常吃 |
| 星期排课 | 计划 → 排课方式；提醒 → 调整训练日安排 | 每计划独立设置；未排的星期休息；循环模式继续支持；编辑和切换不改历史 |

## 数据与规则

- 本地新增 `training_plan_schedules`、`training_supersets`、`favorite_foods`、`training_reminder_settings`、`weekly_report_日期` 和 `weekly_seen`；现有云备份会包含这些普通本地键。
- 训练组的 `type` 缺省视为正式组；超级组另外保存动作的 `supersetId`。额外添加的组、类型和配对能在重新进入当天记录时恢复。
- 明确的动作库 ID 优先；旧动作 ID 仅在映射唯一时合并，冲突身份不混算。历史记录不做破坏性迁移。
- 估算 1RM 使用 1–12 次的有效负重组。自重、超出次数范围和无效组不会生成假估值。
- 训练量采用实际完成的非热身组 `重量 × 次数`。递减组排除加量判定；首次训练建立基线，不显示新纪录。
- 平均摄入分母为有饮食记录的天数。体重变化采用同一完整周内首末两次记录。分享链接只携带摘要，不写入接收者的记录。
- 周报在打开小程序时计算，不依赖后台运行；提醒预览的循环模式假设依次完成每天安排。
